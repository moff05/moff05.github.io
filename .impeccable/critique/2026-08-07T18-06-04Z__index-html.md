#### Anti-Patterns Verdict

**Start here: does this look AI-generated?** Partially, and in one very specific, very fixable way.

**My assessment**: The overall composition (hero → about → work → projects → involvement → off hours → contact, single accent color, serif/mono/sans three-way type split) doesn't scream template — the interactions are specific and mostly non-generic (drag-scroll Off Hours carousel, magnetic hover, the new orbit cluster, real numbers with real correction history). But **every section header uses a numbered, tracked-uppercase eyebrow** ("01 — About", "02 — Work", "03 — Projects", "06 — Off The Clock"). That's not one tell, it's two stacked on top of each other (tiny uppercase eyebrow chip + 01/02/03 sequence) repeated five times down the page. It's the single most recognizable "AI made this" signature in the current build, more than the color palette.

**Deterministic scan** (`detect.mjs`, exit code 2, findings below):
- `numbered-section-markers` — confirms the 01→06 sequence directly. Matches my own read.
- `em-dash-overuse` — 47 em-dashes across body copy. A real, systemic writing-cadence tell, not a one-off.
- `overused-font` (14 hits) — flags Inter and Instrument Serif as increasingly common AI-generated-site defaults. **Not treating this as an actionable finding right now** — PRODUCT.md already names this exact tension explicitly and made the call that a full palette/type rework isn't in scope today; composition and copy carry the burden instead. Flagging here so it's not silently ignored.
- `layout-transition` (5 hits) — `transition: width/height/max-height` on the cursor dot/ring, nav-underline, accordion, and scroll-progress bar. All small-element or infrequent; real perf impact is close to zero. Only the accordion's `max-height` transition (real content reflow) is worth a second look if it ever visibly janks.
- `broken-image` (1 hit, line 1103) — **false positive**. It matched the literal text `<img>` inside a CSS comment explaining the off-card transform fix, not an actual tag. Verified: no `<img>` in the file has an empty or missing `src`.

What's dragging the score down is narrower than "redesign this": one repeated structural habit (numbered eyebrows), one isolated component that broke the site's own rule (the tooltip), one real layout gap (hero), and a copy-cadence tic (em-dashes). Fix those four things and this is a strong, honest 35+.

#### Priority Issues

**[P1] Numbered eyebrow + tracked-uppercase label on every section**
**Why it matters**: This is the single pattern the DESIGN.md I just wrote for this project explicitly bans, and the detector independently confirmed it. It's on About, Work, Projects, Off Hours (Involvement is unnumbered, oddly inconsistent with the rest). For a candidate whose whole pitch is "I build things that aren't templates," the site's own scaffolding undercuts that in the first five seconds.
**Fix**: Drop the number, or drop the pattern entirely. A bare section name ("Selected experience.") already carries the information; the "01 —" prefix and the small tracked "ABOUT"/"WORK" chip above it aren't adding anything a recruiter needs — they're decorating, not informing.
**Suggested command**: `$impeccable typeset` or `$impeccable distill`

**[P1] `.orb-tooltip` combines a hairline border with a 30px-blur shadow**
**Why it matters**: Textbook ghost-card pattern, and it directly contradicts the "shadow OR border, never both" rule this project's own Elevation section states. It's the one place on the page where the "no ghost cards" discipline slipped.
**Fix**: Keep the border, drop the shadow (or cut it to ≤8px blur) — the tooltip already reads clearly as a raised element next to a floating photo; it doesn't need both signals.
**Suggested command**: `$impeccable polish`

**[P2] Hero's text column leaves a large unused vertical gap**
**Why it matters**: `.hero-main` is `align-items: center` in a 2-column grid where the portrait is much taller than the name + rotator text stack. On wide viewports the name sits vertically centered in a very tall row, leaving visible empty space above and below it relative to the photo. This is the concrete version of "fill space."
**Fix**: A few real options, not mutually exclusive — shorten the photo's effective height (crop/aspect-ratio) so the row height matches the text more closely; or add something real to that column (not filler) that uses the space; or switch to `align-items: start` and accept the space sits at the bottom instead of split top/bottom. Want to see options before I touch it — this is a real layout call, not a one-line fix.
**Suggested command**: `$impeccable layout`

**[P2] `--muted` on `--bg-deep` fails WCAG AA by a hair (4.31:1 vs 4.5:1 required)**
**Why it matters**: `--muted` (#6b6862) on `--paper-deep` (#e9e2d6) is used for small label text (e.g. the Projects nav rail's metadata). Everywhere `--muted` sits on plain `--bg` or `--surface` it passes (4.7–5.2:1); only the `bg-deep` combination fails, and only just.
**Fix**: Darken `--muted` by a couple percent lightness, or reserve it for `--bg`/`--surface` only and use `--ink-soft` on `--bg-deep`.
**Suggested command**: `$impeccable audit`

**[P3] 47 em-dashes across body copy**
**Why it matters**: A well-known AI-writing cadence tell, and it's systemic rather than concentrated in one paragraph. Doesn't break anything, but it's a real, fixable voice signal.
**Fix**: In the densest passages (About prose, Projects "Problem"/"What I Built" paragraphs), swap roughly half the em-dashes for periods, commas, or parentheses. Don't need to eliminate them — two or fewer per paragraph reads as normal writing, not a tic.
**Suggested command**: `$impeccable clarify`
